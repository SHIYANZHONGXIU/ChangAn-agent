## 二、必须先修

### 1. 默认设置会阻止可视浏览器访问正常网页

- **用途**：允许域名为空时，应与主聊天网页工具一样，允许经过公网校验的网页。
- **问题与复现**：工作台将空字符串直接分割为 `[""]`，浏览器代理收到非空集合 `{''}`，任何正常主机都不匹配；`https://example.com` 得到 `domain is not approved: example.com`。同样的输入规范化成空集合后可通过模拟公网地址校验。
- **最小修复**：浏览器入口复用主聊天域名处理：去空白、转小写、过滤空项，再传给代理。保留公网地址检查。
- **不修的后果**：首次使用保持默认设置时，浏览器窗口能打开，网页仍可能全部加载失败；单纯“窗口已启动”的验收发现不了此问题。

位置：[工作台入口](C:/Users/HongLin/Desktop/Agent/workbench.py:57)、[代理接入](C:/Users/HongLin/Desktop/Agent/visual_browser.py:44)、[域名判断](C:/Users/HongLin/Desktop/Agent/network_safety.py:16)。本次复现了权限判断层，未重新打开 Chromium 验收整条页面加载链路。

### 2. 并行 Agent 完全没有接入长期记忆

- **用途**：用户在主聊天保存的通用偏好与项目事实，应按相同范围供并行任务使用。
- **问题与复现**：并行入口创建 `Agent` 时没有传入 `memory_lookup` 和 `memory_extract`，任务元数据也没有稳定项目编号。离线模型记录显示：即使两个记忆开关都开启，分析、执行、核验三个请求的记忆数量仍分别为 `0、0、0`，没有执行自动提取回调。相同记忆交给主聊天引擎时，三个阶段均收到两条记录。
- **最小修复**：提交任务时保存稳定项目编号；在并行入口按同一用户/项目范围读取记忆。自动候选继续尊重开关、确认流程，并保存可查看的并行任务来源，不能伪造主聊天消息来源。
- **不修的后果**：主聊天能记住的规则，交给并行 Agent 后失效；用户容易误认为记忆随机丢失。

位置：[并行 Agent 创建](C:/Users/HongLin/Desktop/Agent/parallel_agents.py:145)、[主聊天已接入的对照](C:/Users/HongLin/Desktop/Agent/desktop_app.py:2070)。

## 三、应该修复

### 3. 并行任务审核失败后，恢复按钮无法继续任务

- **用途**：任务达到轮数仍未通过时，增加轮数后应能利用已保存进度继续。
- **问题与复现**：执行结束返回 `failed` 会存为 `failed`，但恢复入口只接受 `interrupted/stopped/error`。离线任务失败后增加轮数到 5，仍报“仅中断、停止或异常任务可以恢复”。主引擎本身已有对失败检查点继续处理的逻辑。
- **最小修复**：并行恢复允许 `failed`，沿用原检查点及用量，仍检查任务是否已停止；增加“失败→增加轮数→恢复”的验证。
- **不修的后果**：只能重新开任务，无法使用界面承诺的恢复流程，还可能重复产生模型用量。

位置：[失败状态保存](C:/Users/HongLin/Desktop/Agent/parallel_agents.py:137)、[恢复条件](C:/Users/HongLin/Desktop/Agent/parallel_agents.py:104)。

### 4. 自动记忆提取失败后，被标成完成且没有重试入口

- **用途**：提取失败不应丢失已经生成的回答；暂时失败后也应可以单独补做提取。
- **问题与复现**：提取回调抛出模拟临时存储错误后，回答正常保留，但检查点仍写 `memory_extraction_done=True`。恢复同一任务后提取总次数仍为 1，不会重试；预算不足、取消也采用相同完成标志。这是现有测试明确接受的行为，属于恢复能力缺口。
- **最小修复**：区分成功、跳过与失败；提供单独“重新整理记忆”入口，利用现有来源指纹防重复。不要为了补记忆重新执行回答或文件操作，也不要无提示自动重复付费请求。
- **不修的后果**：用户明明开启了自动提取，却可能长期没有候选，只能重新发送或手动保存。

位置：[完成阶段](C:/Users/HongLin/Desktop/Agent/orchestrator.py:1071)、[无条件完成标记](C:/Users/HongLin/Desktop/Agent/orchestrator.py:1081)。

### 5. 已保存不等于能召回：同义表达和“继续上次”容易漏记忆

- **用途**：将已经保存的事实找出来，供模型回答。
- **问题与复现**：只按英文词和中文双字片段打分。虚构记录“毕业院校：我毕业于南京大学。”重新打开数据库后，问“我的毕业院校是哪所？”命中 1 条；问“我的母校是哪所？”和“继续上次的内容。”均为 0 条。当前请求最多选 6 条、标题加正文合计 5000 字；仅使用当前任务文字查询，没有利用聊天主题补足检索。这是 README 已说明的能力限制，不是数据库丢失。
- **最小改进**：先补充常见同义词与近期会话主题，建立自然问法验收；仍不足时再加入语义检索及重排。单纯多塞历史或增加条数不能解决无关键词命中，也不保证模型正确使用。
- **不改的后果**：用户换个说法就像没记住；长聊天超出近期历史窗口后也无法可靠接续。

位置：[关键词检索](C:/Users/HongLin/Desktop/Agent/long_term_memory.py:154)、[主聊天查询输入](C:/Users/HongLin/Desktop/Agent/desktop_app.py:2070)。

- **用途**：用户不安装 Python 也能验证独立版 MCP 链路。

- **最小修复**：加入明确的演示服务启动模式和打包资源，或在独立版隐藏当前不可用的演示入口；不能继续给用户生成错误配置。

## 四、还需理解的两个边界

**换版本后看不到旧记忆，可能是换了数据目录。** 当前路径规则会让项目内 EXE 使用项目 `data`，移到独立目录后使用 `%LOCALAPPDATA%/ChangAn/data`，显式设置的 `CHANGAN_DATA_DIR` 优先。模拟两种摆放位置确实解析为不同路径。此次没有观察到两个现存库互相冲突，也没有迁移或合并数据；如果需要改善，先显示当前数据目录，再提供显式导入，不能直接混合覆盖。位置：[路径规则](C:/Users/HongLin/Desktop/Agent/app_runtime.py:17)。

**外部记忆观察器故障与长安 SQLite 无关。** 当前会话的外部观察器报告 `429 / USAGE_LIMIT_EXCEEDED / WEEKLY_LIMIT_EXCEEDED`，即每周用量超限。早前的 `USER_INACTIVE` 是账户未激活；两者属于服务端账户/额度问题，不能当作长安本地记忆实现失败的证据。可由用户点击 <http://localhost:37777/restart> 重启，但额度未恢复时重启不能消除限额；应等待额度重置，或检查该服务账户、API 配置及额度。本次未重启或改动外部记忆服务。

长期记忆的实用方案是“保存→检索→随请求提供参考”。它不要求训练模型。当前 LoRA 实验没有达到预设增益、未接入桌面，也不能让远程 GPT/DeepSeek 自动记住每次聊天。历史小样本模型评测不能证明真实长期使用已经可靠；本次没有重跑收费评测或训练。
