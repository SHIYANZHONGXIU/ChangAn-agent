# 长安长期记忆实施计划

日期：2026-11-02。状态：自动记忆候选已接入；第二轮30组虚构会话与1.5B LoRA v2筛选已完成。GPT/DeepSeek第二轮开发集完成，留出集因旧入口超出本机500,000 token预算而部分未运行；价格未知，未继续调用。LoRA v2未超过直接提示基线，适配器未启用。首轮结果见[首轮验收](自动记忆与模型实验验收.md)，第二轮证据与限制见[第二轮评测与LoRA v2](长期记忆第二轮评测与LoRA-v2.md)。此前113项回归是首轮记录，本轮新增改动后的完整回归另行验收。

## 目标与实施方向

建议先把长期记忆接入现有长安：在新聊天、重启和更换模型后，仍能使用用户授权保存的事实、偏好和项目状态；每条记忆可查看来源、纠正和删除。下文保留原阶段目标；实际已完成范围以首版验收记录为准。

沿用现有 Python、CustomTkinter 和模型请求接口。先使用 Python 标准库 SQLite 与支持中文的关键词/子串检索，不新增向量数据库；检索不足时再依据失败样例升级。首版不要求本地 GPU。

## 当前接入点

- `desktop_app.py`：任务启动时组装最近 12 条上下文，可在此关联项目、聊天、用户消息编号，并提供记忆管理入口。
- `orchestrator.py`：分析、执行、核验共享上下文，但尚无独立长期记忆；新增独立数据字段，避免把记忆当作系统指令。
- `persistence.py`：已有聊天独立存储、原子保存与迁移，应复用项目和聊天标识，不重写聊天存储。
- `tests/`、`scripts/run_checks.py`：沿用既有测试体系；记忆功能先用虚拟资料与模拟服务验证。
- `.gitignore` 与发布说明：新增运行数据库及其附属文件的排除规则，避免公开用户记忆。

## 1. 先建立可判分的虚拟测试

构造带时间顺序的连续会话，覆盖精确事实、新会话与重启、偏好更新、项目待办、未知问题、项目隔离、引用与歧义、删除纠错、模型切换、提取失败。先固定预期结果，再开始实现。

验收：每个样例明确来源、当前有效值、允许读取的范围和预期答案。存储、隔离、更新、删除等确定性用例必须全部通过；生成回答的判分规则在实验前固定，不用审核模型的通过意见代替实际评分。失败先修样例和标注。

## 2. 实现记忆存储、中文检索与更新

新增小型独立存储模块，记录本机用户范围、项目范围、记忆类型、内容、来源聊天与消息、创建与更新时间、有效状态和修订关系。先支持手动保存、检索、修改与删除，再接自动提取。写入使用事务，格式错误不得破坏已有数据。

通用偏好与项目记忆分别处理；按稳定项目编号过滤，不能只靠提示词要求模型自行隔离。检索限制条数与内容长度，避免无限扩大上下文。

验收：关闭并重开存储后记录仍可检索；中文查询能命中基础样例；不同项目不串用；明确的新值替代旧值，歧义不静默覆盖。失败区分存储错误、过滤错误和检索遗漏。

## 3. 接入授权提取与模型使用

用户明确说“记住”时支持保存；自动提取先生成候选，由用户确认后生效。优先使用当前用户明确陈述，引用材料、网页与模型猜测不直接成为已确认事实。不批量扫描已有私人聊天，不保存密钥。

任务开始检索有效记忆，以独立的数据区提供给分析、执行和核验，保留来源与时间。当前用户要求优先于历史偏好。提取请求纳入已有取消、重试与预算逻辑；提取失败不影响正常聊天。

验收：新聊天可以使用已确认记忆，近期上下文仍然有效；旧消息中的引用指令不被升级为授权；候选格式错误有反馈且不损坏已有记录。失败按提取、检索、上下文组织、回答依次定位。

## 4. 增加管理界面与删除规则

提供“记忆”入口，支持查看、搜索、编辑、删除、来源定位，以及暂停保存和使用记忆。运行详情显示本次命中条目，主聊天保持简洁。项目移动、聊天移动、归档和删除要有明确规则：项目记忆不能因聊天移动而自动泄露给另一项目。

“忘记”后，不仅从数据库检索中移除，还要清理仍会参与请求的上下文、候选、缓存和检查点副本，防止旧聊天再次触发自动提取。与备份、历史运行记录有关的保留和清除范围须在界面说明，恢复备份不能悄悄复活已删除记忆。

验收：修改即时生效；删除后重新提问、重启、恢复任务均不会重新注入失效记忆。使用临时测试窗口检查按钮、长文本、项目切换和关闭流程。失败先停用相关路径，修正后再开放。

## 5. 验证双模型接续与成本

单模型闭环通过后，让模型 A 使用会话并保存确认记录，再让模型 B 在新会话读取同一组记录。使用一致的问题、记忆内容和生成预算；记录实际端点与模型标识，不把模型名称或列表可见视为调用成功。

比较无长期记忆、可容纳的完整历史、滚动摘要与外部检索记忆。数据按时间推进，禁止读取未来记录；测试答案不作为记忆直接保存。记录事实正确、偏好遵循、更新、未知时不编造、输入量、延迟与费用。

验收：先通过模拟接口集成测试，再单独记录真实模型结果。真实服务不可用时保留失败原因，不以模拟结果代替。已有 GPT、DeepSeek 接口可作为候选；是否可用以实际调用为准。

## 6. 回归、桌面验收与交付

运行原有回归与新增记忆用例；使用临时数据目录进行实际窗口操作和重启验证，确认原有聊天、队列、审批、停止及任务恢复未受影响。保留升级前数据备份，提供停用记忆功能和恢复旧版本的步骤。

交付源码、虚拟测试数据、测试结果、记忆管理说明、Windows 启动方式及限制记录。结果保存在独立验证目录，并更新原交接文档中的实施状态；对外发布时排除记忆数据库、聊天和私人资料。

## 首版之后：LoRA 与科研分支

完成上述六步后，再评估是否开展固定基础模型的 LoRA 小实验。先明确训练权限、开放权重模型、GPU 显存和预算；普通聊天 API 不能直接用于训练和加载任意适配器。

只选已确认的稳定偏好，与同模型下的直接提示、仅外部记忆、仅 LoRA、外部记忆加 LoRA 比较。精确事实与项目状态继续由外部记录管理。无可重复的质量收益或总成本收益，就停止 LoRA 分支。跨模型参数迁移、MoE 与研究创新性需另外设计实验，不列为首版承诺。

## 首次实际开发的交付范围

先完成第 1、2 步：虚拟会话样例、SQLite 存储与中文检索、更新删除、重启与隔离测试。通过后再接模型与界面，让最早的交付可以独立验证。

默认建议是产品能力优先、接入现有长安；若用户希望独立科研项目，应先调整目录和评测重点。真实历史资料导入、GPU 训练和额外付费服务不由此计划自动启动。

2026-11-01首版完成存储、中文检索、手动确认管理和三阶段参考注入，当时没有调用付费模型或运行训练。2026-11-02已增加自动候选、确认管理、来源聊天级联删除及持久化遗忘意图，并使用虚构资料完成24次真实请求尝试和60步LoRA筛选。随后补充了不调用模型的3种子×100快照记忆存储压力验收（每个种子603项检查通过），以及LoRA多种子结果汇总与能力保留门槛。3个LoRA种子的格式通过率均值为0.889±0.096，基础问答均值为0.250±0.250，基础能力门槛未通过。两个真实端点外部记忆条件各10/10；不能据此证明优于摘要或完整历史。LoRA暂不扩大训练。外部导出副本、项目实际文件、服务商请求无法由本机自动删除；真实模型长会话、多种子正式评测和更强基线仍是后续事项。
