# 长安商业化推进路线

日期：2026-11-02。本文是拟议路线，尚未完成市场验证，也不是上线承诺。最初仅整理计划；随后已按用户授权完成首批费用与预算改进，见[本批验收](商业化首批-费用与预算验收.md)。本批142项本地回归通过，没有调用收费 API，也没有发布软件。

## 产品方向

建议首版定位为：面向使用 Windows 的个人开发者，提供多模型协作、项目记忆、可恢复执行的本地项目工作台。先围绕“理解已有项目 → 修改文件 → 运行检查 → 交付可审查结果”形成稳定闭环。用户画像与付费意愿需要访谈确认；科研、写作、办公先作为候选场景，不同时做成多个产品。

拟议卖点是任务跨聊天与重启后可以继续、项目记忆可查可改可删、执行前能看修改、费用和错误有记录。是否优于现有工具必须用相同任务实测，暂不宣传长期记忆、质量、速度或费用优于竞品。视觉可以借鉴熟悉的交互方式，发布版使用长安自己的名称、图标、文案和素材。

建议商业模式先采用用户自带 API 密钥（BYOK），软件授权费用与模型调用费用分开；普通聊天和项目文件无需为此先建设云端同步。统一代付模型费用、团队账户与云端同步均在验证需求后再投入。此建议尚待产品负责人确定。

## 当前起点与缺口

- 已有项目与聊天、附件、工具审批、恢复、产物记录、外部记忆等基础能力；本地验收文件记录125项测试通过，不能由此认定所有真实场景可靠。
- 第二轮真实接续评测的开发集完成，留出集不完整。旧版入口累计515,475 token，超过本机设定500,000 token上限；价格未配置，实际费用未知。新预算预留仅有离线验证。
- LoRA v2已完成三种子筛选，未表现出超过直接提示的格式收益，保持实验状态；产品完善不依赖它。
- 本轮没有验证安装包、新电脑兼容、市场需求或付费转化；本地文件清单未见正式许可证，发布前还要核对公开仓库和依赖授权。

详细实验依据见同目录《长期记忆第二轮评测与LoRA-v2.md》，测试记录见 `outputs/verification/2026-11-02/checks.json`。

## 阶段一：验证首批用户与核心任务

目的：确认谁会持续使用、为什么付费，避免只按功能数量开发。

实施：找5—10位目标用户，记录他们正在做的真实项目任务、现用工具的困难、可接受的资料外发范围和费用。每人提供1—3个可授权测试任务，不索取密钥或私人完整聊天。选出最常见的一个工作流，写一页产品范围和20个可核验任务。

交付：用户画像、问题记录、核心工作流、验收任务及优先级。这里的访谈人数和任务数量是建议起点，并非已完成指标。

验证：用户能说明实际损失的时间或成本，愿意用自己的任务参加连续试用；同时记录不愿使用与不愿付费的原因。若没有重复需求，先缩小或调整场景，不进入账号、支付或云端平台建设。用户访谈可与阶段二并行开展。

## 阶段二：把费用、执行和恢复做可靠

目的：先解决可能造成超支、误改文件、重复操作和丢失任务的问题。

实施：

1. 核对桌面聊天、工具循环、审核、自动提取、重试和实验脚本的所有请求入口，统一记录输入、输出、估算标志、币种和计价来源。未配置价格必须显示“费用未知”，不能显示免费；达到本机预算时停止新请求。请求前预留输出额度，重试也占用量；已发请求的实际计费仍以服务商为准，账户侧限额需服务商支持。
2. 普通对话优先一次调用；需要操作项目的任务再走分析、执行与核验。提供清楚的运行模式和用量说明，不默认每条消息都调用三个模型。
3. 核验“ask for approve”和“full access”的实际边界。修改前可看差异，写入后有版本；恢复时遇到结果不明的命令或写入，先核实副作用，不自动重放。
4. 补充断网、429、请求中断、磁盘写入失败、进程退出、数据迁移失败的故障用例。检查停止时子进程清理与界面状态；将恢复状态和失败原因写清楚。
5. 核对模型接口能力：流式、图片、工具调用、思考参数、上下文与价格。保留用户选择，明确兼容协议及供应商；不把中转显示的模型名字当作底层模型身份的证明。

交付：可追踪的请求用量、可靠恢复、审批与差异流程、脱敏诊断包、关键故障回归报告。

验证：关键故障用例中已提交消息与已保存产物不丢失；恢复不静默重复有副作用的操作；未批准的操作不执行；预算拦截不误记成模型答错。先用模拟服务验证，真实端点只在另行确定的预算下小规模验证。任一关键项失败，先修复再扩展试用。

## 阶段三：交付不需要配置开发环境的 Windows 版本

目的：让普通用户拿到软件就能开始使用。

实施：锁定依赖与构建版本，制作可重复构建的安装包；增加首次运行引导、模型连接检查、中文错误说明、数据位置与导出入口。应用与用户数据分离，升级前备份并验证迁移；更新包验证完整性和来源，失败可退回。公开收费发行前落实适当的代码签名与分发方式，不要求用户关闭系统防护。

体验验收贯穿本阶段：真实窗口检查浅色/深色、常见屏幕缩放、窄窗口、中文输入、图片粘贴、拖入文件、代码复制、长对话滚动、停止与恢复。根据试用反馈改现有界面；仅在测得当前框架确实限制体验时，再决定是否迁移前端。

交付：候选安装包、构建清单、升级与回退说明、首次使用说明、真实截图验收记录。

验证：在至少两套干净 Windows 环境上完成“安装 → 配置自己的模型 → 选择文件夹 → 完成任务 → 重启接续 → 升级 → 卸载”。无需手动安装 Python；升级不丢聊天、记忆和附件；卸载默认保留用户数据，并明确告知位置。失败先修打包、依赖或迁移，不让用户手改文件解决。

## 阶段四：把核心工作流做成值得付费的能力

目的：从能回答问题提升到能稳定交付用户可用的结果。

实施：优先实现项目读取、修改差异、用户确认、实际检查、产物预览与回滚的一体流程；根据项目类型运行合适的语法、测试或数据检查。界面明确区分“模型认为通过”和“实际检查通过”，保留具体证据。用户不能运行的检查应显示未执行。

长期记忆继续围绕实际错误改善：命中来源可查、过时值能纠正、跨项目不串用、删除后不重新注入、当前要求优先于历史偏好。只有失败样例证明现有中文检索不足时，才增加语义检索；不先引入大型向量基础设施。

冻结独立产品任务集，比较单模型、当前多模型流程和改进流程的完成率、人工修正次数、耗时与费用。验收答案由实际文件、测试或人工标准支持，不仅使用模型自评；保留失败任务和未发送请求。实验中每道格式题通过不等同任务内容正确。

交付：一个完整场景的产品体验、真实任务评测报告、清楚的已知限制。若多模型流程没有抵消成本与等待时间，保留单模型作为默认，多模型变为按需选项。

## 阶段五：小范围持续试用，验证是否值得收费

目的：确认可靠性与用户价值可以在开发者之外重复出现。

实施：邀请首批用户连续试用2—4周，记录安装完成、首次独立完成任务、重复使用、任务失败和支持问题。数据最小化，诊断上传由用户主动选择；默认不上传聊天正文、文件、记忆和密钥。每周修复高频阻碍，再更新候选包。

拟议放行条件：关键任务有重复成功证据；没有未处理的数据丢失、越权或严重泄密问题；部分用户愿意实际付费。以实际购买或明确付费试用验证，点赞、下载量和“感兴趣”不替代付费证据。先制定付费假设，再观察，不根据一个用户随意确定正式价格。

交付：试用反馈、留存与付费意愿记录、版本变更、支持工作量和继续/调整/停止结论。若用户不复用，回到阶段一或四处理原因，暂缓收费平台开发。

## 阶段六：商业发布与持续维护

目的：建立可交付、可退款、可维护的收费产品。

实施：根据试用反馈确定软件授权方式、试用范围、支持边界和价格；API费用与软件费用分别展示。仅建设必要的授权、支付、订单与退款功能。若做客户端授权，不以客户端内置共享密钥作为收费安全机制；支付确认由可信服务处理，保留失败恢复与对账记录。

发布前核对源码、依赖、模型权重和素材许可证；更换历史上已暴露的凭据，检查发布包不包含个人数据。明确哪些内容会发给模型服务、数据保留与删除范围、第三方服务故障处理、用户服务条款与隐私说明。面向不同市场的登记、税务、备案与生成式AI相关要求，需结合实际运营方式由当地专业人员确认，不能由这份路线认定合规。

建立稳定版/测试版、签名与版本校验、更新回退、漏洞反馈、支持与恢复手册；逐版本记录验收证据。公开GitHub、官网与发布渠道时只提供核验过的能力描述，避免宣称任意权限隔离、绝不丢失、记忆完全正确或绝对预算保证。

验证：完成授权开通/失效、支付回调重复、退款、更新失败、故障支持演练；用户能区分软件授权费用、模型费用和未执行的任务。未满足关键要求时继续限制试用范围，不扩大销售承诺。

## 阶段七：有需求证据后再扩展

按真实付费需求选择投入：团队权限与审计、多设备同步、企业私有部署、可靠的本地模型选项、浏览器与办公专用流程。云端同步前先设计租户隔离、访问控制、冲突处理、备份与删除，不直接同步现有数据库文件。

LoRA仅在特定客户任务上有足够授权数据、合适的本地基础模型，并且对比提示与外部记忆产生可重复收益时重新立项。可以先接入未微调的本地模型，再判断LoRA；不把自研模型、跨模型通用适配器或自动训练私人聊天设为商业首版前提。

## 近期实施顺序与决策点

费用与预算首批已完成本地验收：未知费用提示、共享预算预留、逐次记账和历史用量恢复已接入；真实计费仍待小额联调。下一批工程优先顺序：停止/故障/恢复专项验收 → Windows安装包与干净环境验收。同步准备首批用户和核心任务，再根据试用确定界面调整与产品工作流。按阶段验收推进，目前不承诺固定商业上线日期。

需要产品负责人确定的事项：首批目标用户与核心场景、是否接受BYOK首发、软件授权模式、真实模型测试额度、目标发行市场。它们影响优先级和运营责任；本文给出了默认建议，没有代替用户作出最终商业决策。

暂不投入：持续扩大LoRA训练、没有测量依据的整体前端重写、全平台同时发布、统一代付全部模型、复杂团队云端平台。先用最少功能证明产品可靠且有人持续使用并愿意付费。
