# 自动记忆提取、真实模型接续与 LoRA 首轮验收

日期：2026-11-02。开发位置：Agent。功能接入桌面软件；模型实验使用虚构资料，与真实聊天、配置和记忆库分开。

## 现在怎么使用

重启长安，打开“设置与模型 → 运行”，开启“自动整理待确认记忆”。此开关默认关闭；“使用已确认的长期记忆”控制回答是否检索记忆，两者独立。

开启后，每轮成功回答会额外调用当前 GPT，只提取本条用户文字，不扫描旧聊天、助手回答、网页或附件。每次最多5条，消息超过8000字或包含已识别的凭据格式时跳过。提取遵循任务的停止、重试和预算设置，失败不破坏已有回答或已确认记忆；所选模型或服务可能不支持输出长度参数，接口错误会记录为提取失败。

点击侧栏“记忆 → 待确认”，可以查看候选、原文证据与原消息，编辑后“确认保存”，也可以“忽略候选”。候选只属于产生它的项目，未确认不会进入模型上下文。同名同类记忆显示原内容，并在替换前再次核对新旧内容；并发修订会拒绝覆盖，需重新选择核对。想保存成通用偏好，可以在已确认区手动建立通用条目。

成功提取、确认和拒绝都关联消息来源；同一消息恢复时不反复提取，删除已确认记忆不会因重跑原消息而自动复活。移动或删除聊天会清除其待确认候选，已确认项目记忆仍留在原项目。删除记忆只停止使用它；“彻底忘记来源聊天”会删除整个来源聊天的消息、附件、运行记录、检查点、产物、聊天备份，以及该聊天产生的记忆、候选和提取指纹。它不会删除外部项目实际文件、已经导出的副本或服务商已收到的请求。

新增数据表与现有已确认记忆共用 `data/memory/memory.sqlite3`；升级只新增表，不覆盖旧记忆。退出时正常保存；不把整个 `data/` 上传到公开仓库。

## 真实模型接续结果

使用本机已配置的 OpenAI 兼容端点，实际请求模型标识为 `gpt-6.1-sol` 与 `deepseek-v4-pro`，思考强度均为 `medium`，温度0。请求名称和服务响应名称仅是端点标识，无法由客户端核验中转背后的模型权重。

测试按时间推进：先记录项目代号、日期和回答偏好，再更改日期并记录新进度；第二个快照不能影响第一个快照。每条件共10题，覆盖事实、更新、旧事实保留、项目接续、未知、隔离与表达格式。比较条件使用相同问题及2048输出token上限，摘要在对应时间点生成，两模型复用同份摘要与确认记录。

| 条件 | GPT | DeepSeek |
|---|---:|---:|
| 无长期记忆 | 3/10 | 3/10 |
| 提供完整历史 | 10/10 | 10/10 |
| 提供滚动摘要 | 10/10 | 10/10 |
| 检索已确认外部记忆 | 10/10 | 10/10 |

另做一次真实接续：GPT提取“请记住”消息，脚本只确认预先标注的虚构内容，重新打开SQLite，再让DeepSeek从新请求中读取。代号与日期2题都通过。这里的脚本确认只用于虚构实验；日常聊天仍由用户确认。

最初含“虚构项目”的假设式陈述被提取器返回0条，说明提取仍可能遗漏；明确“请记住”的补充样例提取成功。四条件实验的外部记忆使用固定、预先确认的控制记录，自动提取候选另存，不把模型生成的内容直接当成标准答案。

原始实验有1次超时、2次因达到总用量阈值未发请求。失败记录保留，随后只补测这3项，并做上述接续。合计24次真实请求尝试，服务返回79414 tokens；一次失败请求是否计费仍由服务商决定。本机输入输出价格均为0，因此实际费用未知，“0估算”不代表免费。初次60000 token阈值与补测20000阈值均在请求之间检查，单次已发请求可使统计越过阈值。

评分器v2修正了两处确定性错误：允许正确回答新日期时注明旧日期已取消；“三条编号”必须恰好三条。保留原回答、原报告与旧评分，不覆盖失败、不为改分再生成答案。

这是两个时间快照的单次小样本筛选。完整历史、摘要和外部记忆都达到相同分数，尚未证明外部记忆有质量或成本优势；该模型接续实验也没有完成真实模型长会话、统计显著性或多轮随机种子评测。后补的存储压力与LoRA多种子筛选见下文。

证据：`outputs/experiments/2026-11-02_015741-memory/`，原始 `report.json`、补测 `recovery-020744/report.json`、复核 `results-v2.json` 与 `报告-复核.md`。

## LoRA 实际做了什么

### 通俗解释：LoRA 是什么

LoRA 是一种让模型学会新偏好的轻量训练方法。可以把原来的大模型想成一整本厚书：LoRA 不重写整本书，而是在特定位置附上一小份可拆装的“补充页”。训练时冻结原模型，只更新这份较小的附加参数，因此训练和保存通常比改动整个模型省资源。

这份“补充页”不是普通的长期记忆。它更适合学习稳定的输出风格或任务习惯；精确事实、项目进度和需要随时修改或删除的内容，更适合放在长安的外部记忆库里。LoRA通常依赖它训练所用的基础模型及结构，不能把为某个开源模型训练的适配器直接当成GPT、DeepSeek等服务的通用记忆文件。

本项目的首轮实验就是训练这样一份附加参数：它在6道格式题中答对5道，但基础问答从4/4降到1/4。因此它目前只是实验产物，长安日常聊天没有加载它；这说明不能只看格式任务变好，还必须确认模型原有能力没有明显退化。

固定基础模型：`Qwen/Qwen2.5-0.5B-Instruct`，版本 `7ae557604adf67be50417f59c2c2f167def9a775`。只使用人工模板编写的虚构稳定格式偏好，20条训练、6条未见过的建议问题、4条基础问答；问题与编号跨组不重复。没有导入真实聊天，也没有将模型自生成回答当成训练标签。

先完成2步冒烟，再执行预先设定的60步筛选；随机种子42，LoRA秩8、alpha16，目标为注意力q/v投影，学习率0.0002，梯度累积2，最长256 token，不静默截断训练标签。固定最后一步验收，不按测试集挑选检查点。

| 条件 | 格式偏好（6题） | 基础问答（4题） |
|---|---:|---:|
| 基础模型 | 0/6 | 4/4 |
| 直接提示偏好 | 0/6 | 4/4 |
| 外部偏好数据 | 0/6 | 1/4 |
| 仅LoRA | 5/6 | 1/4 |
| 外部偏好＋LoRA | 1/6 | 1/4 |

基础模型共494032768参数，其中540672参数参加训练。RTX4080上60步训练7.513秒；训练阶段峰值GPU张量分配约1.14GiB，这是PyTorch分配指标，不是整机显存峰值。整轮含模型加载和5组生成评测约78秒。软件实际版本、数据与代码哈希、每步损失和每题回答均保留。

保存适配器后重新加载，同一问题输出完全一致；停用适配器后，与基础模型对应输出一致。适配器文件未合并进基础模型，也没有修改桌面软件配置。

**这版没有通过启用门槛。** 仅LoRA在这6题上改善格式，但4道基础题从4/4降到1/4，说明这个小实验存在过拟合或指令遵循退化；0.5B模型对外部JSON数据本身也表现较弱。格式评分不验证建议是否正确，个别建议仍不可靠。当前不接入日常聊天，不宣称提升长期记忆，不扩大到更多数据或更长训练。

若继续LoRA研究，应另设新协议：改善直接提示与外部数据的基线，加入“当前要求覆盖历史偏好”的训练样例和通用能力保留数据，增加测试规模与随机种子，再在固定模型上比较。精确事实和项目进度仍由外部记忆管理；该适配器不能直接装到GPT或DeepSeek的普通聊天API，也不具备任意跨模型通用性。

证据：`outputs/experiments/2026-11-02_020828-lora/`，适配器在 `adapter/`，完整原始记录 `report.json`、严格评分 `results-v2.json` 与 `报告-复核.md`。2步冒烟保存在 `2026-11-02_020327-lora/`。两轮都不是正式多种子科研结果。

## 本轮继续推进：压力验收与多种子入口

已新增离线记忆存储压力脚本 `experiments/memory/stress.py`。先完成每组12快照，再使用3个固定种子、每组100次时间快照及500条较长干扰记录，检查最新值替换、重新打开存储后读取、最多6条/5000字符限制、项目隔离及来源聊天删除。最终共1809项断言通过。它不调用模型，也不模拟应用进程重启。证据、复跑及限制见[本轮压力与多种子验收](长会话压力与多种子验收.md)。

LoRA脚本新增 `--seed` 参数，每次运行会把实际种子和解析后的协议单独写入结果目录，不覆盖原协议。可用 `experiments/lora/aggregate.py` 汇总多个已完成的独立结果；汇总前会拒绝重复种子、不同数据/代码或不一致协议，并逐个种子检查基础能力退化。只有格式收益、通用能力保留、保存重载一致和停用回滚都通过，才会把 `continue_lora` 判为真；当前没有满足这一门槛，因此适配器继续停用。

示例：

```powershell
python experiments/memory/stress.py --seeds 7,23,41 --snapshots 100
.\.venv-lora\Scripts\python.exe experiments/lora/run.py --steps 60 --seed 7 --device cuda
python experiments/lora/aggregate.py outputs/experiments/<seed7目录> outputs/experiments/<seed23目录> outputs/experiments/<seed41目录>
```

压力脚本验证的是存储和边界，不代表模型回答质量；多种子LoRA筛选也不是正式科研结论。真实模型长会话评测仍需明确预算后单独运行。

### 多种子实际结果（2026-11-02）

在同一虚构数据、代码和60步协议下完成3个种子（42、1337、2026）的本地LoRA筛选。格式题通过率均值为 `0.889 ± 0.096`，但基础问答均值只有 `0.250 ± 0.250`；三个种子分别为 `0.25/0.00/0.50`。保存后重载和停用回滚在3个种子均一致，格式收益门槛通过，但基础能力保留门槛未通过，因此结论仍是**不继续扩大训练、不启用适配器**。

最新结果文件：`outputs/experiments/2026-11-02_112151_474362-lora-multiseed-summary.json` 与同名 `.md`（初次汇总单独保留）；三个独立运行目录分别为 `outputs/experiments/2026-11-02_110916-lora-seed42/`、`outputs/experiments/2026-11-02_111021-lora-seed1337/`、`outputs/experiments/2026-11-02_111123-lora-seed2026/`。

## 复跑与目录

双击根目录“运行记忆接续评测.bat”会调用收费API，单独生成新结果目录。普通“运行测试.bat”只运行本机模拟测试，不产生API消费。

双击“运行LoRA实验.bat”会使用可选的 `.venv-lora` 环境、下载固定模型并训练虚构数据，结果也进入 `outputs/experiments/`，不会切换日常模型。当前电脑已准备环境；新增训练库安装在该环境中，PyTorch通过 `shared_torch_runtime.pth` 复用既有CUDA环境，原环境依赖未安装或升级。共享路径仅保存在被忽略的虚拟环境内；移动或删除原环境后，需要按以下命令准备独立环境，不能只复制当前 `.venv-lora`。

新电脑可在本目录终端依次运行（CUDA索引应与显卡及驱动相容）：

```powershell
python -m venv .venv-lora
.\.venv-lora\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu130
.\.venv-lora\Scripts\python.exe -m pip install -r experiments/lora/requirements.txt
.\.venv-lora\Scripts\python.exe experiments/lora/run.py --steps 2
```

确认冒烟通过后，再去掉 `--steps 2` 运行60步。模型下载到标准Hugging Face本机缓存 `%USERPROFILE%/.cache/huggingface/hub/`；适配器、日志、数据和结果留在Agent的 `outputs/experiments/`。下载与训练会占用磁盘和显存，桌面聊天本身不要求安装这些训练依赖。

源码与协议在 `experiments/memory/`、`experiments/lora/`；每次正式入口会保留协议、数据哈希、代码副本。评分复核不调用模型：

```powershell
python experiments/summarize.py --memory outputs/experiments/2026-11-02_015741-memory --recovery outputs/experiments/2026-11-02_015741-memory/recovery-020744 --lora outputs/experiments/2026-11-02_020828-lora
```

## 工程验收与回退

本轮113项本地测试通过，0失败、错误、跳过，回归本身没有真实API请求；真实模型实验另计。新增覆盖聊天遗忘意图的路径校验、异常退出后恢复和级联清理、长会话压力验收及LoRA多种子汇总门槛。整体覆盖候选校验、来源、确认、更新、拒绝、取消、隔离、移动、队列、恢复、界面开关、报告复核与原有功能。真实Tk窗口的明暗候选列表及设置已截图检查，0回调异常；记录在 `outputs/verification/2026-11-02/auto-memory/`。

连续操作发现Tk字体可能在后台线程析构并卡住任务。已改为在应用存续期间由主线程定时执行循环对象回收，销毁窗口后恢复原回收设置；修复后完整回归通过。

停用自动提取只需关闭其开关；已确认记忆是否参与回答由另一开关控制。LoRA从未启用到桌面软件，无需回滚聊天模型。源码回退包在 `archive/2026-11-02-before-auto-memory-015055/源码回退.zip`，不含私人数据；关闭应用后恢复旧源码即可，新增SQLite表可保留。现有聊天、私人记忆和密钥没有导入实验或训练。
